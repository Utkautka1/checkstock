# CheckStock — где сейчас товар?

Веб-прототип складского учёта для менеджера: видит, где товар, сколько доступно и что отправлено.

**Стек:** Python 3.12 · FastAPI · PostgreSQL 16 · React 18 · TypeScript · Tailwind CSS · Docker Compose

---

## 🚀 Быстрый запуск

```bash
git clone <repo-url>
cd checkstock
docker compose up --build -d
```

Ждём ~30 секунд, затем заполняем тестовыми данными:

```bash
docker compose exec backend python seed.py
```

Открываем в браузере: **http://localhost:5173**

Логин: `admin` / Пароль: `admin123`

## ✅ Проверка сценариев

### 1. Экран остатков
Перейдите на `/stock` → видны все товары по складам: физически / доступно / резерв FBS.

### 2. Приход товара
Нажмите «Оформить приход» → выберите товар, склад, количество.

### 3. Перемещение между ФФ
`/movements` → «Создать перемещение» → выберите маршрут.
После создания статус `in_transit` (товар в пути, списан с источника).
Нажмите «Подтвердить приёмку» — товар зачислится на склад-получатель.

> **Идемпотентность:** повторное нажатие «Подтвердить» безопасно — товар не спишется дважды.

### 4. Резерв FBS
`/shipments` → вкладка FBS → «Новая отправка» → «Зарезервировать».
Доступный остаток уменьшится, физический не изменится.
«Отправить» → товар покидает склад. «Отмена» → резерв снимается.

### 5. Отправка FBO
`/shipments` → вкладка FBO → «Новая отправка».
Товар сразу списывается физически и числится «в пути».
«Принято маркетплейсом» → закрывает отправку.

### 6. Нехватка товара
Попробуйте зарезервировать больше, чем доступно — получите ошибку с указанием нехватки и подсказкой про другие склады.

### 7. Удаление склада
`/warehouses` → кнопка удаления.
Склад помечается неактивным, **история и остатки сохраняются** в БД.
На экране остатков удалённый склад отображается со статусом «Удалён».
В `/warehouses` включите «Показать удалённые» — увидите его с датой удаления.

### 8. История операций
`/history` — полный журнал всех движений с типом операции, откуда/куда, количеством и временем.

## 🏗️ Архитектура и ключевые решения

### Учёт остатков
- **Три показателя:** `quantity_physical` (физически), `quantity_reserved` (резерв FBS), `quantity_available = physical - reserved`
- **Перемещение:** товар сразу списывается физически при создании движения → `in_transit`. При подтверждении приёмки зачисляется на склад-получатель.
- **FBS:** создаёт резерв (physical не меняется) → после отправки списываются оба (physical - reserved).
- **FBO:** физически списывается при отправке, числится «в пути» в таблице Shipments.

### Идемпотентность подтверждения
Перед зачислением проверяем `movement.status == COMPLETED` — повторный вызов безопасен.

### Мягкое удаление складов
`is_active=False` + `deleted_at` — история и остатки не удаляются из БД. На экране остатков удалённый склад виден с меткой.

### Нехватка с контекстом
При нехватке на конкретном ФФ API возвращает точные цифры: доступно / нужно / физически / в резерве, и подсказывает про другие склады (для FBO).

### Аудит
Каждая операция записывается в `stock_operations` — полная история с привязкой к движениям и отправкам.

## 📡 API

Swagger: http://localhost:8000/docs

Основные эндпоинты:
- `POST /api/auth/login` — получить JWT
- `GET  /api/stock` — остатки по всем складам
- `POST /api/stock/receive` — приход товара
- `GET  /api/stock/operations` — история операций
- `GET  /api/warehouses` — список складов
- `POST /api/movements` — создать перемещение
- `POST /api/movements/{id}/confirm` — подтвердить приёмку
- `POST /api/shipments/fbs/reserve` — резерв FBS
- `POST /api/shipments/fbs/{id}/ship` — отправить FBS
- `POST /api/shipments/fbo/ship` — отправить FBO
- `POST /api/shipments/fbo/{id}/receive` — приёмка FBO
